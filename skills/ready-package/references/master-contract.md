# Master Artifact Contract

3단계 산출물의 고정 형식이다. 정보가 없다는 이유로 필수 섹션을 삭제하지 않고 `확인되지 않음`과 필요한 검증을 기록한다.

## package/master/source-structure.md

- 마스터의 원본이 된 제출 문서마다 `source_id`, 파일 경로, 형식, 총 페이지 또는 최상위 블록 수를 기록한다.
- 블록 표: `block_id`, 페이지, 유형(제목·문단·목록·표·이미지·캡션), 원문 요약, 부모 블록, 원본 순서.
- 이미지와 재사용 자산: 원본 위치, 크기·비율, 캡션, 사용 위치.
- 추출할 수 없는 항목은 누락 사실을 그대로 남긴다.

## package/master/resume.md

원본 이력서의 형식 골격을 유지한다. 문서 상단에 주석 없이 본문만 두고, 판정과 근거는 `master-notes.md`에 분리한다.

고정 요소:

1. 상단 식별 — 이름, 직무 정체성 한 줄, 연차, 연락 수단
2. 대표 성과 요약 — 3~5개, 각 항목은 문제와 변화가 함께 읽히는 한 문장
3. 핵심 역량 — 목표 직무축의 반복 요건에 대응
4. 경력 — 회사, 기간, 역할, 대표 프로젝트와 개인 기여
5. 학력·기타 — 원본에 있는 경우만

## package/master/career-history.md

경력기술서. 프로젝트 단위로 문제, 역할과 결정 범위, 행동, 결과(기준 시점·비교 대상 포함), 학습을 확장한다. 이력서와 같은 사실을 더 깊게 설명하되 새로운 사실을 만들지 않는다.

## package/master/portfolio-storyboard.md

포트폴리오 페이지 편집 지시서. 실제 디자인 작업은 이 환경 밖에서 수행한다.

페이지 표의 필수 열: `page`, 원본 내용 요약, 판정(`keep` / `compress` / `move` / `remove` / `new`), 이동 대상 위치, 판정 이유, 이 페이지에서 읽혀야 할 핵심 문장, 필요한 자산, 근거 ID.

추가 섹션:

1. 전체 구성 — 대표작과 보조작의 순서와 목표 분량
2. 첫 화면 원칙 — 독자가 3초 안에 알아야 할 것
3. 케이스별 서사 — 문제→판단→산출물→검증→결과의 페이지 배치
4. 압축 원칙 — 반복되는 목표·가설·회고 페이지의 처리
5. 삭제 후보와 보류 — 사용자 승인이 필요한 구조 변경
6. 자산 목록 — 재사용 이미지와 필요한 신규 자산

## package/master/cover-letter-skeleton.md

1. 지원 동기 구조 — 회사 문제 인식, 내 경험의 접점, 기여 가설의 순서
2. 경험 연결 규칙 — 어떤 유형의 회사 신호에 어떤 경험 카드를 연결하는가
3. 재사용 문장 — 사실만 담긴 문장. 회사별 수식어는 포함하지 않는다
4. 금지 표현 — 근거 없는 열정 표현, 회사 가치 문구의 단순 반복
5. 회사별로 반드시 새로 쓰는 부분

## package/variants.md

직무축 A/B/C마다 다음을 규정한다.

- 상단 메시지 한 문장
- 대표 경험 선택과 노출 순서
- 강조할 직무 언어와 피할 언어
- 이력서·경력기술서·포트폴리오에서 달라지는 지점
- 이 축에서 쓰지 않는 경험과 그 이유

사실을 바꾸는 변형, 경험을 새로 만드는 변형은 허용하지 않는다.

## package/assignment-framework.md

1. 과제 유형별 평가 기준 추출 방법
2. 기본 구조 — 문제 정의, 평가 기준, 대안 비교, 선택·실행, 지표·리스크
3. 표기 규칙 — 주어진 사실 / 외부 조사 / 개인 가정
4. 첫 화면 규칙 — 결론과 핵심 지표
5. 모의 과제 1편과 자체 리뷰 결과

## package/interview-assets.md

1. 경험 자산 8개 유형 — 성과, 실패, 갈등, 반대 의견, 설득, 고객 문제, 긴급 판단, 구조 개선
2. 각 자산 — 결론, 문제, 판단, 행동, 결과, 회고, 재현성, 연결된 경험 카드 ID
3. 후속 질문 대비 — 데이터, 대안, 실패, 확장성
4. 컬처핏 — 회사 가치 문구가 아니라 실제 판단·협업 사례를 연결하는 규칙
5. 레퍼런스 — 후보, 관계, 함께한 프로젝트, 확인 가능한 결과, 동의 여부, 회사 정책 확인 사항

## package/readiness.md

1. 판정 요약 — 서류·전형·면접 3축의 `passed` / `needs-work` 상태와 판정일
2. 축별 테스트 결과 — 각 테스트 항목과 근거
3. 리허설 기록 — 사용한 JD, 단계별 소요시간, 병목, 재작업이 필요했던 지점
4. 제출 가능 판정 — 품질을 유지하며 1~2주 안에 제출 가능한가
5. 보완 과제 — 항목, 이유, 되돌아갈 단계
6. 버전 — 마스터 버전, 프로필 버전, 변경 이유
